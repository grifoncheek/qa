# Тест-кейсы

Всего тест-кейсов: **36** (UI — 16, API — 20).

По типам: позитивных — 22, негативных — 14. По приоритету: высокий — 18, средний — 16, низкий — 2.

Исходный файл для импорта в Test IT — [test-cases.csv](test-cases.csv) (разделитель ;, UTF-8). Шаги в одной ячейке разделены символом |, при импорте маппятся в Steps. Модуль соответствует папке/сьюту, Тип и Приоритет — соответствующим полям.

## Авторизация

**UI-01 Вход с валидными данными standard_user** (Позитивный, приоритет — Высокий). Предусловия: Открыта страница https://www.saucedemo.com. Шаги: 1. Ввести логин standard_user; 2. Ввести пароль secret_sauce; 3. Нажать Login. Ожидаемый результат: Открывается каталог /inventory.html со списком товаров.
**UI-02 Вход с неверным паролем** (Негативный, приоритет — Высокий). Предусловия: Открыта страница логина. Шаги: 1. Ввести логин standard_user; 2. Ввести неверный пароль; 3. Нажать Login. Ожидаемый результат: Сообщение Username and password do not match any user in this service, пользователь остаётся на странице логина.
**UI-03 Вход заблокированного пользователя** (Негативный, приоритет — Высокий). Предусловия: Открыта страница логина. Шаги: 1. Ввести логин locked_out_user; 2. Ввести пароль secret_sauce; 3. Нажать Login. Ожидаемый результат: Сообщение Sorry, this user has been locked out, вход не выполняется.
**UI-04 Проверка обязательности полей формы** (Негативный, приоритет — Средний). Предусловия: Открыта страница логина. Шаги: 1. Нажать Login с пустыми полями; 2. Ввести логин и оставить пароль пустым; 3. Нажать Login. Ожидаемый результат: Последовательно выводятся сообщения Username is required и Password is required.
**UI-15 Выход из системы и защита страниц** (Позитивный, приоритет — Средний). Предусловия: Выполнен вход. Шаги: 1. Открыть меню; 2. Нажать Logout; 3. Перейти на /inventory.html напрямую. Ожидаемый результат: Возврат на страницу логина, прямой переход к каталогу недоступен.
## Каталог

**UI-05 Отображение списка товаров** (Позитивный, приоритет — Высокий). Предусловия: Выполнен вход standard_user. Шаги: 1. Открыть /inventory.html; 2. Проверить карточки товаров. Ожидаемый результат: Отображаются 6 товаров, у каждого название, цена и изображение, счётчик корзины пуст.
**UI-06 Сортировка Name (A to Z)** (Позитивный, приоритет — Средний). Предусловия: Открыт каталог. Шаги: 1. Выбрать в сортировке Name (A to Z); 2. Сравнить порядок названий. Ожидаемый результат: Товары отсортированы по возрастанию названия.
**UI-07 Сортировка Price (high to low)** (Позитивный, приоритет — Средний). Предусловия: Открыт каталог. Шаги: 1. Выбрать Price (high to low); 2. Сравнить цены. Ожидаемый результат: Товары отсортированы по убыванию цены.
## Корзина

**UI-08 Добавление одного товара** (Позитивный, приоритет — Высокий). Предусловия: Открыт каталог. Шаги: 1. Нажать Add to cart у Sauce Labs Backpack. Ожидаемый результат: Кнопка меняется на Remove, счётчик корзины показывает 1.
**UI-09 Добавление трёх разных товаров** (Позитивный, приоритет — Высокий). Предусловия: Открыт каталог. Шаги: 1. Добавить три разных товара; 2. Открыть корзину. Ожидаемый результат: Счётчик показывает 3, в корзине три позиции с корректными названиями и ценами.
**UI-10 Удаление товара из корзины** (Позитивный, приоритет — Средний). Предусловия: В корзине минимум один товар. Шаги: 1. Открыть корзину; 2. Нажать Remove у товара. Ожидаемый результат: Товар исчезает из списка, счётчик уменьшается на 1.
**UI-11 Сохранение корзины после перезагрузки** (Позитивный, приоритет — Средний). Предусловия: Товар добавлен в корзину. Шаги: 1. Обновить страницу каталога. Ожидаемый результат: Корзина и счётчик сохраняются, товар остаётся в списке.
## Оформление заказа

**UI-12 Успешное оформление заказа** (Позитивный, приоритет — Высокий). Предусловия: В корзине есть товары. Шаги: 1. Открыть корзину; 2. Нажать Checkout; 3. Заполнить First Name, Last Name, Zip; 4. Нажать Continue; 5. Нажать Finish. Ожидаемый результат: Сообщение Thank you for your order и кнопка Back Home.
**UI-13 Ошибка при пустом First Name** (Негативный, приоритет — Высокий). Предусловия: Открыт шаг Checkout: Your Information. Шаги: 1. Оставить First Name пустым; 2. Заполнить остальные поля; 3. Нажать Continue. Ожидаемый результат: Сообщение Error: First Name is required, переход на следующий шаг не выполняется.
**UI-14 Итоговая сумма равна сумме товаров** (Позитивный, приоритет — Средний). Предусловия: В корзине два и более товара, открыт шаг Overview. Шаги: 1. Сравнить Item total с суммой цен товаров; 2. Проверить Tax и Total. Ожидаемый результат: Item total равен сумме цен, Total = Item total + Tax.
## Меню

**UI-16 Сброс состояния приложения** (Позитивный, приоритет — Низкий). Предусловия: В корзине есть товар. Шаги: 1. Открыть меню; 2. Нажать Reset App State. Ожидаемый результат: Корзина очищена, счётчик сброшен, кнопки товаров снова Add to cart.
## API: Health-check

**API-01 Проверка доступности сервиса** (Позитивный, приоритет — Средний). Предусловия: API доступно. Шаги: 1. Отправить GET /ping. Ожидаемый результат: Ответ 201 Created.
## API: Auth

**API-02 Аутентификация с валидными данными** (Позитивный, приоритет — Высокий). Предусловия: Известны admin и password123. Шаги: 1. Отправить POST /auth с валидными данными. Ожидаемый результат: Ответ 200, в теле есть непустой token.
**API-03 Отказ при неверных учётных данных** (Негативный, приоритет — Высокий). Предусловия: API доступно. Шаги: 1. Отправить POST /auth с неверным паролем. Ожидаемый результат: Ожидается 401 Unauthorized. Факт: 200 и reason Bad credentials — BUG-10.
## API: Booking

**API-04 Создание брони с валидными данными** (Позитивный, приоритет — Высокий). Предусловия: API доступно. Шаги: 1. Отправить POST /booking с полным набором полей. Ожидаемый результат: Ответ 200, есть bookingid, тело повторяет переданные данные.
**API-05 Чтение брони по ID** (Позитивный, приоритет — Высокий). Предусловия: Бронь создана, известен её ID. Шаги: 1. Отправить GET /booking/{id}. Ожидаемый результат: Ответ 200, поля совпадают с созданными.
**API-06 Получение списка ID броней** (Позитивный, приоритет — Средний). Предусловия: API доступно. Шаги: 1. Отправить GET /booking. Ожидаемый результат: Ответ 200, массив объектов bookingid.
**API-07 Фильтр по имени клиента** (Позитивный, приоритет — Средний). Предусловия: Есть бронь с заданным firstname. Шаги: 1. Отправить GET /booking?firstname={name}. Ожидаемый результат: Ответ 200, среди ID есть ID созданной брони.
**API-08 Фильтр по датам** (Позитивный, приоритет — Средний). Предусловия: Есть бронь с заданными датами. Шаги: 1. Отправить GET /booking?checkin=...&checkout=. Ожидаемый результат: Ответ 200, возвращён ID подходящей брони.
**API-09 Полное обновление PUT с токеном** (Позитивный, приоритет — Высокий). Предусловия: Есть token и созданная бронь. Шаги: 1. Отправить PUT /booking/{id} с токеном и новыми данными; 2. Прочитать бронь. Ожидаемый результат: Ответ 200, GET возвращает обновлённые данные.
**API-10 Частичное обновление PATCH с токеном** (Позитивный, приоритет — Средний). Предусловия: Есть token и созданная бронь. Шаги: 1. Отправить PATCH /booking/{id} с полем firstname; 2. Прочитать бронь. Ожидаемый результат: Ответ 200, изменился только firstname, остальные поля сохранены.
**API-11 Обновление без токена** (Негативный, приоритет — Высокий). Предусловия: Есть созданная бронь. Шаги: 1. Отправить PUT /booking/{id} без токена. Ожидаемый результат: Ответ 403 Forbidden, данные не изменены.
**API-12 Удаление брони с токеном** (Позитивный, приоритет — Высокий). Предусловия: Есть token и созданная бронь. Шаги: 1. Отправить DELETE /booking/{id} с токеном; 2. Прочитать бронь. Ожидаемый результат: DELETE возвращает 201, GET возвращает 404.
**API-13 Создание без обязательного поля** (Негативный, приоритет — Высокий). Предусловия: API доступно. Шаги: 1. Отправить POST /booking без firstname. Ожидаемый результат: Ожидается 400. Факт: 500 — BUG-01.
**API-14 Отрицательный totalprice** (Негативный, приоритет — Высокий). Предусловия: API доступно. Шаги: 1. Отправить POST /booking с totalprice=-100. Ожидаемый результат: Ожидается 400. Факт: 200 — BUG-07.
**API-15 checkout раньше checkin** (Негативный, приоритет — Высокий). Предусловия: API доступно. Шаги: 1. Отправить POST /booking с checkout раньше checkin. Ожидаемый результат: Ожидается 400. Факт: 200 — BUG-08.
**API-16 Битый JSON** (Негативный, приоритет — Средний). Предусловия: API доступно. Шаги: 1. Отправить POST /booking с телом {oops. Ожидаемый результат: Ответ 400 Bad Request.
**API-17 Неподдерживаемый Content-Type** (Негативный, приоритет — Средний). Предусловия: API доступно. Шаги: 1. Отправить POST /booking с Content-Type text/plain. Ожидаемый результат: Ожидается 415. Факт: 500 — BUG-04.
**API-18 Чтение несуществующего ID** (Негативный, приоритет — Средний). Предусловия: API доступно. Шаги: 1. Отправить GET /booking/999999999. Ожидаемый результат: Ответ 404 Not Found.
**API-19 totalprice в виде строки** (Негативный, приоритет — Средний). Предусловия: API доступно. Шаги: 1. Отправить POST /booking с totalprice в кавычках. Ожидаемый результат: Ожидается 400. Факт: 200 и totalprice null — BUG-06.
**API-20 Невалидная дата в фильтре** (Негативный, приоритет — Низкий). Предусловия: API доступно. Шаги: 1. Отправить GET /booking?checkin=not-a-date. Ожидаемый результат: Ожидается 400. Факт: 500 — BUG-05.
